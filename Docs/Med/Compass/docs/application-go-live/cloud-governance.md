# Cloud Governance #
As applications go through the Argo platform, additional reviews may be required by [Cloud Governance](https://cloudservices.medtronic.com/governance/council/). Cloud Governance meets weekly on Thursdays to review and approve. Gate 2 and Gate 3 *cannot* be done on the same date, so plan two weeks for governance reviews if your application involves Highly Sensitive data.


## Gate 2 - Introduction of Highly Sensitive Data ##

If your application involves [Highly Sensitive](https://mrcsd2.medtronic.com/d2anonserv/getcontentbynamestatus?docbase_name=mrcs&auth=crts_wmuser&format=c2pdf&name=91249-InfoSec-IC&status=Effective) data, [Gate 2 Review](https://cloudservices.medtronic.com/governance/council/#introduction-of-highly-sensitive-ie-phipii-information-gate-2) is required prior to data being introduced into the argo-quarantine or argo-prod clusters. The below artifacts are required in order to go to Gate 2.

### Required Artifacts / Data ##
#### 1. Application Logical Diagram ####
!!!danger
Applications must make every effort to remediate __all__ vulnerabilities and move to the Production cluster. The Quarantine cluster is meant for legacy applications that __CANNOT__ remediate all vulnerabilities without an application re-write.
!!!
Download [Draw.io](https://www.drawio.com/) to alter the below diagram to fit your application.
1. If your application meets requirements to deploy to the __[Argo Production Cluster](../platform-inventory/argo-prod.md)__:
[!file icon="download" text="Argo Production Application Logical Diagram"](../static/architecture/Argo-Prod-Application-Logical-Diagram-EXAMPLE.drawio)
1. If your application __does not__ meet requirements for production, to deploy to the __[Argo Quarantine Cluster](../platform-inventory/argo-prod.md)__:
[!file icon="download" text="Argo-Quarantine Application Logical Diagram"](../static/architecture/Argo-Quarantine-Application-Logical-Diagram-EXAMPLE.drawio)

#### 2. Argo Infrastructure Diagram ####
Infrastructure diagrams for the Argo platform are available below.

Contact [Ash Montebello](mailto:ash.l.montebello@medtronc.com) for any new integrations for your application that need to be added to these diagrams.
!!!

[!file icon="download" text="Argo Prod/Quarantine Cluster Infrastructure Diagram"](../static/architecture/IT-Argo-Prod-Infrastructure-Diagram.drawio)

#### 3. GSO Data and Privacy Assessment Number ####
Complete the [assessment](https://medtronicprod.service-now.com/it?id=sc_cat_item_order_guide&sys_id=10bd221adb726c1014c354f94896192d) and record the PIA or PTA number.

#### 4. Planview ID ####
If applicable for your project.

#### 5. Business Unit ####
Provide the business unit this application belongs to.

#### 6. ServiceNow Business Application CI ####
Provide the ServiceNow Business Application CI name.

#### 7. Data Classification ####
Review the [Personal Data](https://medtronic.sharepoint.com/sites/dataprivacy/SitePages/Personal-Data.aspx) definition and the [Information / Data Classification](https://mrcsd2.medtronic.com/d2anonserv/getcontentbynamestatus?docbase_name=mrcs&auth=crts_wmuser&format=c2pdf&name=91249-InfoSec-IC&status=Effective) levels. This classification will determine the required level of remediation for any vulnerabilities identified within your application.

#### 8. Vulnerability Report ####
Provide the Vulnerability Report for the version of the application you are deploying to production. This report contains both Trivy and Contrast to meet GCISO requirements. This should be provided nightly and during any builds/deployments to anyone who is listed in the `emailNotifyList` of the `appInfo.json`.

GitLab built-in security views:
- [Security Dashboard](https://docs.gitlab.com/user/application_security/security_dashboard/)
- [Vulnerability Report](https://docs.gitlab.com/user/application_security/vulnerability_report/)

Important: if a later scan detects a finding is fixed, mark that finding as **Resolved** in the GitLab Vulnerability Report. If it remains in a non-resolved state, it can still count against your **Risk Score**.

To retrieve the same information, you can also use the UIs of the respective tools:
==- Trivy Report from GitLab
Within GitLab, open the pipeline for the application version being deployed and review the container scanning report generated by Trivy.
- Navigate to the pipeline Security tab and open the vulnerability results for the image.
- Export or download the report artifact and include it in your governance evidence bundle.
===

==- Contrast Report from UI
Within the [Contrast Console](https://app.contrastsecurity.com/Contrast/static/ng/index.html#/f7147a63-299d-4a6d-92db-b7421f2e9b32/applications/ca86973c-105b-4fce-baee-818b9f30fc5e), navigate to the Vulnerabilities tab.
- Filter on the Application by searching for your <appName>-argo and Severity of Critical, High, and Medium
- The filtered list will outline all open issues, which can then be exported:
  ![](../static/security/contrast-export.PNG)
===
